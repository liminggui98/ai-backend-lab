## A. 计价：价目与成本结论

> 三家报价单位都是「元 / 百万 token」，**不需要换算**。要做的只有一件事：
> 按项目的真实输入输出结构，折算成「**元 / 千次问答**」——单价不可比，千次成本才可比。
>
> 折算公式：`单次成本 = 输入 token ÷ 100 万 × 输入价 + 输出 token ÷ 100 万 × 输出价`，再 ×1000 得千次成本。

| --- | --- | --- | --- | --- | --- | --- |

| DeepSeek | deepseek-flash | 空闲 | 无上限 | 1 | 0.02 | 4 |
| 智谱 | glm-4-flash | 全时段 | 无上限 | 0 | — | 0 |

| 百炼 | qwen3.7-plus | 全时段 | 256K ~ 1M | 6 | 1.2 | 24 |

**三点备注**

- **模型名会漂**：请求 `deepseek-chat`，实际返回并计费的是 `deepseek-flash`（已确认两次）。
- **免费不等于零成本**：智谱要确认 QPS 上限、每日额度、数据是否用于训练；这三条没确认前只能进开发链路。
- **百炼有上下文上限**：1,048,576 token，超过直接不可用，不是「按最后一档算」。

### A2. 场景成本（元 / 千次问答）—— 唯一可比的数

> **怎么读这三张表**
> - 「谁便宜」取决于三件事同时取值——**时段 × 缓存命中率 × 输入长度落在哪档**，单看单价会说错话；
> - **S4 专门用来暴露分档**：S1–S3 都在百炼第一档内，只有 S4（30 万 token）会跨到第二档、单价跳 3 倍；
> - 这组数字直接进 W6 的成本模型。

### A3. 四条结论

1. **冷启动时，百炼第一档和 DeepSeek 高峰完全相同**（3.4 / 10.2 / 70.4）——标准档位没有价差，价差全在时段和缓存。
2. **缓存折扣深度差 10 倍**：DeepSeek 命中价 0.04 对输入 2（**省 98%**），百炼 0.4 对 2（**省 80%**）。
   缓存打满时，S3 从 70.4 变成：DeepSeek 空闲 **3.84** / 百炼 **19.2**，差 **5 倍**。
3. **S4 是百炼最贵的一条路**：30 万 token 跨到第二档，冷启动 **1824**，是 DeepSeek 高峰的 3 倍、空闲的 6 倍；即使缓存打满也要 **384**，是 DeepSeek 空闲（10）的 **38 倍**。
4. **DeepSeek 空闲时段始终是半价**，这一条在任何缓存命中率下都成立。

### A4. 三个自问自答

1. **典型场景下最便宜的是谁？**
   单价最低是**智谱（免费）**；但在**生产可用**的前提下，DeepSeek 空闲时段（S2 = 5.1 元/千次）比百炼（10.2）便宜一半。
   「免费」和「最便宜」不是一回事——智谱省的是钱，付的是速度和准确率。

2. **缓存命中率提到 50%，排名会变吗？**
   第一名不变（智谱仍是 0），但第二三名拉开：DeepSeek 高峰 10.2 → 6.77（比百炼低 34%），空闲 5.1 → 3.38（只有百炼的 1/3）。

3. **有没有按次计价、没法折算的？**
   **没有**，三家都按 token 计费，可以直接横向比。但百炼**流式不返回 usage**，成本统计要走非流式采样。

> 上下文窗口、单次最大输出、免费额度这些**不放进价格表**——它们影响「能不能用」，不影响「贵不贵」，混在一起会让这张表失焦。

## B. 能力矩阵

> 口径：**查官方文档确认**（2026-10-29），未经代码实测的已标注。
> ✅ 支持　❌ 不支持　⚠️ 有条件 / 文档未明确

| 能力 | DeepSeek | 智谱 | 百炼 | 关键限制 |
| --- | --- | --- | --- | --- |
| 流式（SSE） | ✅ | ✅ | ✅ | 三家本机实测（C 表） |
| 推理过程单独返回（`reasoning_content`） | ✅ 实测 | 待验证 | ✅ 实测 | DeepSeek 见「思考模式」；百炼 Day 1 实测先流 reasoning 再流 content |
| `response_format: json_object` | ✅ | ✅ | ✅ | 只保证是合法 JSON，**不保证字段**；三家都要求 prompt 里出现 json 字样 |
| `response_format: json_schema`（严格模式） | ❌ | ❌ | ✅ **实测：约束生效，`maxLength` 例外** | DeepSeek API 参考里**没有这个字段**；智谱只给 `json_object`；百炼（`qwen3.7-plus`）实测见 B2 —— **字段/枚举白名单是真强制，长度不强制** |

| 多轮 `tool` 角色回传 | ✅ | ✅ | ✅ | 三家都是 OpenAI 兼容的 `role: "tool"` + `tool_call_id` |
| 图片输入（多模态） | ✅ | ❌ | ⚠️ | **DeepSeek**：`deepseek-flash` 直接支持图片（jpeg/png/gif/webp，单图 ≤32 MiB，单请求 ≤600 张，每图 ≤1024 token）；**智谱**：`glm-4-flash` 是免费**文本**模型，要图片得换 `GLM-4V-Flash`；**百炼**：得换 qwen-vl 系列，而 vl 系列偏偏不支持 tools |
| 自带联网 / 检索 | ✅ | ✅ | ✅ | 形态完全不同：**DeepSeek** 是独立的 Search/Fetch API（不在 chat 请求里）；**智谱** 是 `web-search` 工具；**百炼** 是请求参数 `enable_search: true` |
| 上下文缓存 | ✅ | — | ✅ | DeepSeek 省 98%、百炼省 80%（见 A1）；智谱免费不区分 |
| `tool_choice` 可选值 | auto / none / required | **仅 auto** | auto / none / required | 只有智谱不能强制「必须调工具」，做 Agent 时要注意 |

### B1. 对 W2 / W5 的三个直接影响

1. **结构化输出别指望 `json_schema`**：三家只有百炼支持，且要挑模型。W2 做结构化抽取时，**通用方案是自己校验 + 重试**，`json_object` 之外的能力当成加分项而不是前提。（2026-10-30 实测补充：百炼严格模式的字段/枚举白名单是真约束，但 `maxLength` 不生效 → **客户端仍要全量校验**，见 B2）
2. **强制工具调用只有两家能做到**：智谱 `tool_choice` 仅 auto，意味着「必须调这个工具」在它上面做不到。W5 Agent 的状态机如果要强约束，主线别用智谱。
3. **图片输入会打破「一份代码三家跑」**：DeepSeek 直接支持；智谱、百炼都要换 VL 模型，而百炼的 VL 又和 tools 互斥。多模态功能不要设计成三家的公共能力。

### B2. 实测：百炼 `json_schema` 严格模式（2026-10-30）

> 一次性实验，脚本不落仓库；原始返回留本机。

**环境**：`qwen3.7-plus`（空间级域名）· `temperature 0.3` · `stream false`
**schema**：5 字段全 required —— `order_id`（`pattern ^JD[0-9]{10}$`）、`sku_count`（1–20）、`reason`（四值 `enum`）、`urgent`（`boolean`）、`summary`（`maxLength 40`），`additionalProperties: false`。
**输入**：一段脏客诉（含发票、积分两个干扰问题 + 「尽量详细，能看到的都输出」）。

#### 实验一 · 正常 prompt × 10（看会不会自己违规）

| 判据 | 通过 |
| --- | --- |
| 可 `json.loads` | 10/10 |
| `required` 一个不少 | 10/10 |
| `enum` 合法 | 10/10 |
| 类型正确（int / bool） | 10/10 |
| 无额外字段 | 10/10 |
| **`maxLength: 40` 生效** | **5/10** ← summary 实际 49–65 字 |

#### 实验二 · 诱导违规 × 5（明确要求输出 schema 外的 `invoice_required` / `points_impact` / `confidence`）

| 组 | 结果 |
| --- | --- |
| 严格模式 | **5/5 合规** —— 三个额外字段被全部压掉，只返回 5 个已声明字段，HTTP 200 不报错 |
| 无 `response_format`（同一诱导） | **5/5 违规** —— 带三重反引号围栏、自造 `product_name` / `quantity` / `return_reason`，真的输出了 `invoice_required: true`、`points_impact`、`confidence: 0.95`，同时缺 `urgent` / `summary` |

#### 结论

1. **`strict` + `additionalProperties:false` 是真约束，不是「鼓励」**：最强诱导下额外字段仍被消除 → 说明是服务端解码约束，不是模型自觉。
2. **但不是所有关键字都强制**：`maxLength` 实测 10 次违规 5 次；`pattern` / `minimum` / `maximum` 因模型本来就输出合规值，**无法区分是否被强制**（要专门造违规输入才能验）。
3. **W2 工程结论**：schema 只当「字段与枚举白名单」用，**长度 / 正则 / 数值范围一律在客户端再校验**；`json_object` + prompt 写死字段不可靠（实验二 5/5 翻车），失败重试一次。

> `tok/s` 按「输出 token ÷（总耗时 − 首 token）」由中位数现算，与「逐次 tok/s 取中位数」会差 1–10%，属正常。

### C1. 三次运行暴露的 6 件事

**1. 单次样本会骗人。**
智谱两次总耗时 1,136 / 2,269 ms（差一倍），百炼首 token 454–987 ms（差 2.2 倍）。
拿一次数据下结论，很可能把「这次网络抖了」当成「这个模型慢」。

**2. 「百炼流式不返回 usage」只对 `qwen-plus` 成立。**
`qwen-plus` 的尾帧没有 usage；换 `qwen3.7-plus` 后，尾帧明确带 `usage`（本轮 3 次调用都拿到了 31/283/314 这类数字），
抓原始 SSE 验证过：`{"usage":{"prompt_tokens":16,"completion_tokens":523,"total_tokens":539}}`。
所以计费逻辑不能写死「百炼没 usage」，要**按模型探测、拿不到再退化成估算**。

**3. 推理模型的思考 token 计入 `completion_tokens`。**
同一句「用一句话解释 RAG」，`qwen3.7-plus` 记了 **523 个输出 token**，其中 152 帧是 `reasoning_content`，正文只有约 45 个 token（≈9%）。
按输出价 8 元/百万算，**光思考就约 0.0038 元/次**——成本模型里输出侧不能按 400 token 估，否则低估数倍。这是本轮最重要的发现。

**4. 同一段 prompt，三家 tokenizer 切出的 token 数差 41%（22 / 24 / 31）。**
DeepSeek 22、智谱 24、百炼 31。含义：
- 跨 provider 比「每 token 单价」会失真，**必须比「同一 prompt 的千次成本」**；
- 中文的 token 效率各家不同，长 system prompt 场景差距会被放大。

**5. `deepseek-chat` 第三次返回 `deepseek-flash`。**
Day 1 一次、19:45 一次、本轮 3 次——别名稳定漂移。指标表必须记**实际返回的 model**，否则换模型后历史数据不可比。

**6. 智谱把 RAG 的全称编错，4 次里 3 次。**
它答的是「检索-摘要-排名（Retrieval-Aggregation-Generation）」——**这是错的**，RAG = Retrieval-Augmented Generation。
本轮 3 次里 2 次错（第 1 轮答对），加上 19:45 那次共 **4 次错 3 次**。DeepSeek、百炼本轮全对。
这不是文字游戏：一个连检索增强全称都编错的模型，放到 RAG 项目里做生成端，幻觉风险要按这个水平估。

### C2. 这组数据对选型的影响

实测把「便宜」和「好用」拆成了两件事（全部用中位数）：

| 维度 | 智谱 glm-4-flash | DeepSeek deepseek-flash | 差距 |
| --- | --- | --- | --- |
| 首 token | 596 ms | 879 ms | 智谱反而快 283 ms——它不思考，直接出字 |
| 总耗时 | 1,185 ms | 1,169 ms | **基本持平**（短回答） |

| 事实性 | 4 次错 3 次 | 全对 | — |
| 成本 | 0 | 10.2 元/千次（S2 高峰） | 智谱免费 |

**短回答上两家体感几乎一样**（总耗时 1,185 vs 1,169 ms），第一轮单样本得出的「3.5 倍 / 8.6 倍」是抖动放大的结果。
真正的分水岭在**生成速度 2.7 倍**：输出拉到 400 token 时，智谱约 7.9 s、DeepSeek 约 2.9 s，差 5 s。这条结论目前只有短回答支撑，所以 C3 第一条就是补长回答。
结论仍落在 E1：智谱当开发档，DeepSeek 当生产主线。

**百炼单列**：`qwen3.7-plus` 首 token 775 ms 只是「思考开始」，总耗时 5,242 ms，是 DeepSeek 的 **4.5 倍**。
同价（`<256K` 档 2/8）但总耗时 4.5 倍——**降级能用，不能当主力**，且低延迟链路应该降到非推理的 `qwen-plus`。

## E. 结论（这页最重要）

> 依据：2026-10-29 抄录的价目 + C 表的 3 次实测中位数。价格或模型变了，手动改 A1 的价目、按 A2 的公式重算，再回来改结论。

### E1. 三句话

**1. 主线用 DeepSeek-flash（高峰时段）。**

理由不是便宜，是**稳且快**：首 token 中位数 879 ms、生成 **137.9 tok/s**，是 glm-4-flash（50.9）的 2.7 倍；同一道 RAG 题它 3 次全答对，glm-4-flash 4 次里 3 次把全称编错。
成本（S2 文档问答，RAG 典型）：**10.2 元 / 千次**，折合 **约 1 分钱一次**。

**批处理 / 离线评测排到空闲时段**：输入 2→1、输出 8→4，同场景降到 **5.1 元 / 千次**，**直接省一半**。夜间跑 RAGAS、批量回归、压测，没理由在高峰时段跑。

**2. 降级用百炼 qwen3.7-plus。**

`<256K` 档和 DeepSeek 高峰**完全同价（2/8）**，另一个供应商、另一条链路，适合接 429 和超时。
切换条件：DeepSeek 连续 429，或 P95 > 3 s → 切百炼。两条链路都走 OpenAI 兼容协议，`LLMClient` 已经抹平差异。
**但它不是「更快的备胎」**：`qwen3.7-plus` 是推理模型，首 token 775 ms 只是开始思考，总耗时 **5.2 s**（DeepSeek 的 4.5 倍）。
所以降级分两档：**低延迟链路降到非推理的 `qwen-plus`**，需要推理质量时才用 `qwen3.7-plus`。
**计费注意**：`qwen-plus` 流式不返回 usage，`qwen3.7-plus` 返回（C1 第 2 条）——网关要按模型探测，不能写死。

**3. 智谱 glm-4-flash 只做开发档，不上生产。**

免费（成本 0），适合跑 RAGAS、批量对比、压测——不心疼。但它有两个硬伤：**生成 50.9 tok/s（DeepSeek 的 1/2.7）**、**4 次里 3 次把 RAG 全称编错（事实性最差）**。放进面向用户的链路，省下的钱会用体验还回去。

> 换句话说：**开发期用免费的，生产期用快的，降级用同价的。** 三者不冲突，W6 网关按场景路由即可。

### E2. 什么时候成本会翻车

| 场景 | 谁最贵 | 贵多少 |
| --- | --- | --- |
| 常规 RAG（S2，3.5K 输入） | 三家几乎同价（0 / 10.2 / 10.2） | 只看 DeepSeek 峰谷差，2 倍 |
| 长上下文（S3，32K） | 同上 | 峰谷差 2 倍 |
| **整本文档（S4，300K）** | **百炼 1824 元/千次** | **是 DeepSeek 高峰的 3 倍、空闲的 6 倍** |

**结论**：如果你的产品要把整本手册塞进上下文，**百炼是最贵的那个**（跨到第二档 6/24）。反过来，只要输入控制在 256K 以内，百炼和 DeepSeek 一个价。

> 还有一条不在表里、但更隐蔽：**推理模型的思考 token 按输出价计费**。`qwen3.7-plus` 一句 60 字的回答记了 523 个输出 token（C1 第 3 条），照 A2 的 S2（输出 400）估成本会**低估数倍**。做成本模型前先问清楚「输出 token 里有多少是思考」。

### E3. 缓存是这张表里最值钱的一列

S2（RAG 典型）在三种缓存命中率下：

| 缓存命中率 | DeepSeek 高峰 | DeepSeek 空闲 | 百炼 |
| --- | --- | --- | --- |
| 0% | 10.2 | 5.1 | 10.2 |
| 50% | 6.77 | 3.38 | 7.4 |
| 100% | 3.34 | 1.67 | 4.6 |

两件事：

1. **两家的缓存折扣深度差 10 倍**。DeepSeek 命中价 0.04 对输入 2（省 98%），百炼 0.4 对 2（省 80%）。
   命中率越高，差距越明显：缓存 100% 时 S3 的 70.4 变成 DeepSeek 空闲 **3.84** / 百炼 **19.2**。
2. **RAG / Agent 的 system prompt 是固定前缀，命中率不会低**。把命中率从 0 拉到 50%，DeepSeek 高峰从 10.2 降到 6.77——**省 34%**，比换 provider 划算得多；拉到 100% 能省 67%。

> 所以 W3 做 RAG 时，**prompt 结构要为缓存设计**：固定内容放前面、变量放后面，别把用户问题拼在 system 里。
> 这一条不花钱，但直接影响账单。
