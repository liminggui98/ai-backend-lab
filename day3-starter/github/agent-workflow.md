# agent-workflow

> 物流履约异常处理 Agent：从「查运单」到「处置执行」，中间带状态机、工具幂等、人工审批和注入防护。
>
> **状态：骨架**　创建于 2026-10-29　·　计划 W5 实现，目标 11 月底上线

## 为什么做这个

Demo 里的 Agent 都是「问一句 → 调个工具 → 回一句」。真实业务里会撞上四个问题：

1. **停不下来**：工具报错就重试，重试就死循环；
2. **不敢让它自己干**：退款、改地址这类操作，必须有人确认；
3. **错了没法查**：多步任务跑完，不知道哪一步出的问题；
4. **被一句话带跑**：用户输入里夹一句「忽略上面的指令」，整个流程就改道了。

所以这个项目的重点不是「能调工具」，而是**失控时能停下来、出错时能回放**。

## 场景

```
用户：这单怎么还没到？
  ↓
查运单 → 定位环节（揽收 / 中转 / 派送）→ 判断异常类型
  ↓
生成处置建议 → 【人工审批】→ 执行（催派 / 改约 / 理赔申请）
  ↓
回执 + 全链路 trace
```

## 核心设计

| 模块 | 做法 | 要证明什么 |
| --- | --- | --- |
| 状态机 | 显式节点 / 边 / 条件路由，不用「模型自己决定下一步」 | 流程可枚举、可测试 |
| 最大步数 | 超过 N 步强制终止并回滚 | 死循环跑不掉 |
| checkpoint | 每一步落库，支持中断恢复 | 崩了能从中间接着跑 |
| 工具层 | 幂等键 + 超时 + 权限校验 | 重试不会重复退款 |
| 审批节点 | 危险操作 100% 人工确认 | 模型不能直接动钱 |
| 注入防护 | 输入清洗 + 工具白名单 + 越权校验 | 10 条攻击用例全部拦截 |
| 可观测 | 每步 traceId + token + 耗时 | 一次任务能完整回放 |
