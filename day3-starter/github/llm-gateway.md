# llm-gateway

> 多家模型统一入口：一套 OpenAI 兼容协议，按成本和能力路由，主模型挂了自动切备用，按租户计费。
>
> **状态：骨架**　创建于 2026-10-29　·　计划 W6 实现，目标 12 月初上线

## 为什么做这个

接了三个 provider 之后，业务代码里会出现一地 `if (provider == ...)`，接着是：

1. **谁便宜用谁**——但价格和上下文窗口各不一样，硬编码就再也不敢改；
2. **主模型 429**——请求直接失败，用户看到的是报错；
3. **成本失控**——月底对账才发现某个租户烧了预算；
4. **出问题查不到**——只知道慢，不知道慢在网关、模型还是网络。

网关要做的事：**把「用哪家模型」变成一个可配置、可观测、可回滚的决策。**

## 架构

```
业务方 ──(OpenAI 兼容)──▶ llm-gateway
                            ├─ 协议兼容层（统一入参 / 错误码归一）
                            ├─ 路由（按成本 / 按能力 / 按租户策略）
                            ├─ 令牌桶限流 + 熔断降级
                            ├─ 语义缓存（命中直接返回）
                            ├─ SSE 透传（首 token 不被缓冲吃掉）
                            └─ 计费 + 埋点（token / 延迟 / 成本）
                                   ↓
                    DeepSeek / 智谱 / 百炼 / 本地 Ollama
```

## 核心设计

| 模块 | 做法 | 要证明什么 |
| --- | --- | --- |
| 兼容层 | 统一请求模型 + 统一错误码 | 换上游，业务方不用改代码 |
| 路由 | 按成本 / 能力 / 权重，配置化 | 改一条配置就能换主力 |
| 限流 | 令牌桶（租户级 + 全局） | 单租户打不垮整个网关 |
| 熔断降级 | 错误率触发，备用 provider 接管 | 切换 < 1s 且不中断流 |
| 语义缓存 | 相似问题命中缓存 | 命中率与误命中率都要测 |
| 计费 | 按租户聚合 token 与成本 | 能说清每一分钱花在哪 |
| 可观测 | Micrometer → Prometheus → Grafana | 面板上能看到首 token / 429 / 成本 |
