## 1. 统计口径（可复核）

- **语料**：31 份文件 = Track A（AI / Agent 相关）23 份 + Track B（业务后端 / SRE 参照系）8 份；同源多版本合并后 **27
  个独立岗位**（阿里商品理解 ×3、美团 AI Agent 工程师 ×2、快手可灵后端 ×2），其中 **AI 岗 20 个**、Track B 7 个。
- **排除**：`README.md` 索引；每份 JD 末尾的「## 关键词提炼」段（是对 JD
  的二次摘要，计入会自我放大）；引用块备注；元信息里的「方向 / 招聘人」行（Track B 的「方向」常写「与 AI/Agent 无关」，计入会污染
  Agent 词频）。
- **计入**：元信息表（含「标签」行）+ 职位描述正文（职责 / 要求 / 优先 / 亮点）。
- **出现次数**：关键词在文本中的非重叠匹配次数； **出现份数**：至少命中一次的 JD 文件数（/31）； **去重岗位**：同源合并后计数（/27）；
  **AI 岗占比**：分母为 20 个去重后的 AI 岗。
- **要求级别**：按去重岗位判断——过半岗位在「任职要求」段提到 → 硬性；出现在「优先/加分」段 → 优先；只在职责或标签出现 → 提及。
- **局限**：同义词做了合并（`LangChain4j` 统计含 LangChain / LangGraph；`评测` 含泛化的「评估」）；词频反映「招聘方写什么」，不等同于「面试考什么」；9
  年经验岗（360 / 搜狐）会拉高「团队管理」类词。

**两个反直觉的读法**

1. **低频 ≠ 不重要**：Embedding、向量库、混合检索、Rerank 是 RAG 的实现细节，JD 用一个「RAG」概括了。它们词频低，但 W3–W4
   的项目一必须做——面试深挖就挖这里。
2. **高频 ≠ 高筛选权重**：安全、Token 成本、评测大量出现在「职责」段而不是「任职要求」段，说明招聘方希望「你来之后能做」，而不是「简历上必须有」。这类词的正确用法是
   **项目 bullet 里给数字**，不是技能栏里堆名词。

## 5. 三个反直觉发现

**① 你的实现栈没有市场词。**
31 份 JD 里 Spring AI **0 次**、LangChain4j **严格 0 次**；被点名的是 LangChain / LangGraph（6 份）。这不是让你换栈——用 Java
做 AI 应用正是差异化——而是简历要写「 **Spring AI / LangChain4j（Java 版 LangChain 生态）**」，把「LangChain /
LangGraph」作为认知项列出，让 ATS 和 HR 能扫到。面试话术： *「Java 侧我用 Spring AI 和 LangChain4j 落地，LangGraph
的状态图思想我读过，项目二的状态机就是按这个思路自己写的。」*

**② 计划模板里的三个词，市场不要。**
`多租户` 0 份、`结构化输出` 实际 1 个岗位、`LoRA 微调` 2 份（一份是小红书「四选一」里的后训练方向，一份是美团「轻量级微调」）。W6
计划里的「多租户」可以直接砍掉，把时间还给 Token 成本与限流熔断（分别 8 岗、4 岗）。

**③ 评测、安全、成本是「工程化信号」，不是「关键词」。**
它们的价值不在被 HR 扫到，而在面试时证明「你做的不是 demo」：

- 评测：11 个岗位，只有 5 个写进任职要求——但美团把「任务完成率、工具调用准确性、安全边界」写进了职责；
- 安全：9 个岗位，要求里只有 2 个——但「危险操作人工确认、注入/越权用例全拦截」是你 9 年工程经验最自然的迁移点；
- Token 成本：8 个岗位——九号、阿里 MaaS 是核心职责，你的网关项目「每百万 token 成本下降【30%】」正好对上。

**三条纪律**

1. **项目 bullet 比技能栏更贴 JD**：现有简历的网关项目已经写了「多 provider 路由、切换 <1s、限流熔断、每百万 token
   成本下降【30%】」（数字待 W6 压测后填），RAG 项目写了「混合检索 + RRF + Rerank + RAGAS」——这些词都命中，v1 只需要重排技能栏，不用改项目。
2. **没上线的不要写**：今天写的 v1 里，项目二/三的指标还是空的（成功率、平均步数、单任务成本），先留【】，W5/W6 上线后再填。
3. **AI Coding 要写「用过 + 会 review」**，不是「了解」：美团把「Claude Code / Cursor / Copilot 实战 + 对 AI 生成代码的 review
   判断力」写成了硬性要求。
